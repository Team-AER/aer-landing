Speech people hear. Machines can’t transcribe.

Muffliato is designed to add a bounded perturbation to recorded speech so automatic transcription returns nothing, while listeners still hear every word.

Get the code Talk to us

Research implementation. Built and tested on CPU; efficacy against the real model is untested.

Who needs this

People whose recordings leave their hands, and who need the words to stay with listeners rather than become searchable text.

  • Confidential meetings in regulated work

    Legal, healthcare, board and HR teams whose call audio ends up with a counterparty’s AI notetaker: wiretap, CIPA and BIPA claims against Otter.ai survived dismissal in August 2026, and New York City Bar opinions 2025-6 and 2026-2 address AI recording of clients.

  • Voice talent, narrators and audiobook publishers

    Nine BIPA class actions over AI use of voices came in May 2026, and the July 2025 SAG-AFTRA Interactive Media Agreement set AI voice-consent terms; Muffliato targets transcription of delivered masters and pre-release samples, not voice cloning.

  • Screeners and dailies

    Studios already pay per copy for forensic watermarking, yet TPN and MPA standards have no control for AI extraction, and a screener can tolerate a faint audible mark that a master cannot.

  • Confidential interviews and source material

    Documentary and investigative producers, and newsroom legal and standards teams, holding raw interview audio that should be heard by editors and never turned into a transcript by a tool they don’t control.

Today that means recorded files. The model reads a whole utterance before it writes, so it does not protect a live call.

What it does to the audio

One forward pass of a generator writes a signal that is added to the clip. These are properties of that signal by construction; whether it suppresses transcription is still to be measured.

  • Bounded on every sample

    A hard L∞ limit: the output is tau · tanh(z), so no sample moves more than tau, with 0.00025 as the quiet target.

  • Zero DC

    The generator solves for a centring bias inside the tanh, so the perturbation averages zero to numerical precision and no budget goes on a constant offset.

  • Phase-preserving

    It reads and writes a complex STFT, FFT 512 and hop 160 on 16 kHz mono, predicting real and imaginary parts rather than a magnitude mask.

  • Loudness-aware

    A log-RMS input feature keeps the clip’s absolute level, because a fixed tau weighs more on quiet speech than on loud.

  • Whole-utterance context

    Six dilated temporal blocks see about 2.55 s around each frame, and two Transformer layers attend across the whole clip.

  • Universal pattern plus a per-clip residual

    The hybrid preset adds a learned 16,000-sample pattern, noise channels and an optional gain head under the same bound: 1,535,297 parameters, against 1,518,720 for the default generator.

How it works

The training and evaluation pipeline is implemented end to end and covered by CPU tests. None of the steps that load the real model have been run yet.

  1. 1

    Prepare a manifest

    List native 16 kHz mono clips; the manifest freezes each file’s path, SHA-256, length, speaker and reference text, with no silent resampling or padding.

  2. 2

    Predict a perturbation inside the bound

    The generator reads the clip’s complex spectrum and writes an additive signal that stays within ±tau on every sample and averages zero.

  3. 3

    Train against the frozen victim

    The loss is the exact empty-transcript TDT loss of nvidia/parakeet-tdt-0.6b-v3, in stages teacher, self_distill and direct; PGD teachers come from training clips only.

  4. 4

    Optionally refine at evaluation

    Amortised sign-PGD can take a few signed-gradient steps from the generator’s output, and that rate is always reported apart from the generator’s own.

  5. 5

    Evaluate saved audio, then replay

    Saved float WAVs are scored for raw and normalized empty rate, WER, SNR and PESQ/STOI, then replayed on a freshly loaded model before any claim.

Where it fits

Most protections act after a copy exists, or guard the door rather than the file. Muffliato is meant to act before extraction, on the audio itself.

Watermarking
Traces a leaked copy back to its source. It acts after the copy exists and does not stop anyone transcribing it.
Content ID
Matches copies once they are uploaded. Also after the fact.
Crawler tolls and robots.txt
Govern how bots fetch web pages. An audio enclosure that has been downloaded or attached is outside their reach.
Bot blocking
Keeps a notetaker out of the meeting, as VCU, Chapman and Harvard do for third-party bots. It stops the bot, not the audio.
Muffliato
Changes the audio file before any extraction, so the protection travels with the file. Whether it works is not yet measured.

Early, and honest about it

Implementation complete; efficacy untested. This page quotes no suppression rate for Muffliato because there isn’t one yet.

  • Not trained on the real victim

    No pretrained Parakeet inference or GPU training has been run for this network.

  • Efficacy untested

    Lower training loss or a finished checkpoint is not suppression; only decoded, replayed output counts, and there is none yet.

  • Audibility not reviewed

    No listening test has been done. PESQ and STOI thresholds are study gates, not proof that nobody can hear it.

  • Offline, not real-time

    The model is non-causal: it reads the whole utterance before writing, so it works on saved files, not live streams.

  • One victim model

    It targets nvidia/parakeet-tdt-0.6b-v3 with frozen weights and greedy decoding, and makes no claim about other speech recognisers.

  • Digital audio only

    The signal is added to the file. Playback through a speaker into a microphone, compression and resampling are all untested.

What earlier experiments showed

Sibling per-clip PGD experiment, not this network

At tau 0.00025, per-clip optimisation against the same victim emptied 71 of 90 outcomes: 30 clips from 15 speakers, three restarts each. Quality at that budget was PESQ mean 4.46 (p10 4.23) and STOI mean 0.9993 (p10 0.9986).

That shows quiet suppression is feasible when each clip is optimised on its own. It says nothing yet about a one-pass generator.

The bar the project set itself

A provisional quiet gate at tau 0.00025: at least 70% raw-empty transcripts, PESQ mean ≥ 4.0 (p10 ≥ 3.7) and STOI mean ≥ 0.99 (p10 ≥ 0.98). Passing it would still not be a perceptual guarantee.

Run it

The base install runs the CPU test suite with synthetic audio and model doubles. Nothing is downloaded and no GPU is touched.

shell
git clone https://github.com/NidhiBharani/parakeet-suppression-nn
cd parakeet-suppression-nn && python3.12 -m venv .venv && .venv/bin/python -m pip install -e .
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
Tests
98 CPU tests, using synthetic audio and model doubles.
Real victim work
Install -e '.[parakeet,quality]' for NeMo, torchaudio, PESQ and STOI.
Stack
Python 3.12 or later, Torch 2.11, NeMo 3.0. A clean install has not been tested yet.
Presets
11 research configs in configs/, from a one-clip fit to the hybrid tau-continuation run. All default to CPU.
