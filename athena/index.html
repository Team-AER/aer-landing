How an analysis runs

Six stages, each with its own checkpoint, coverage note and journal entries. A later cycle can reuse a finished stage instead of repeating it.

  1. 1

    Intake

    Hash-verified upload into content-addressed storage. The controller never executes the sample; it records who submitted it and to which project.

  2. 2

    Static

    A disposable offline VM runs metadata parsers, entropy, strings and IOC extraction, YARA, capa, FLOSS, Ghidra and TLSH/ssdeep, then is discarded.

  3. 3

    Dynamic

    One compatible disconnected guest, chosen from the ELF header or routed to the Windows worker. Telemetry, PCAP and screenshots are preserved; teardown is verified.

  4. 4

    AI research

    A bounded local model reads the saved evidence through typed tools, within action, run and time budgets. Every exchange is recorded.

  5. 5

    Correlation

    Deterministic links to other samples: shared hashes, indicators and network destinations. No model is involved.

  6. 6

    Report

    Ten fixed sections with coverage notes, written as an immutable revision beside the artifacts.

Seven Linux profiles, one Windows worker

The worker picks the guest from the parsed ELF header: architecture, bitness, endianness, ABI and interpreter. Never from a filename or a model suggestion. PE executables route to the separate Windows worker.

  • No external network. Guests see local DNS and HTTP simulation only. Direct-IP callbacks and TLS are not simulated, and the report records that as a coverage gap rather than a quiet network section.
  • strace sensors on Linux. The behavioural sensor is in-guest strace, which a sample can evade or tamper with. Each run states its sensor provenance and treats guest output as untrusted.
  • Hypervisor telemetry on Windows. x64 and x86 PE run offline under Xen with DRAKVUF: process, file and registry events, descendant tracking, screenshots, bounded observation and verified teardown.
  • Containers. An archive selects one compatible ELF for the parent run and queues every recognised executable child for its own coverage.

Static first, in a VM that is thrown away

Every sample passes through a disposable offline VM before anything runs. The stage writes what each tool found and, just as carefully, what it could not: an unsupported format, a packer it did not open, a limit it hit.

  • Metadata and entropy. PE or ELF headers, imports where available, section entropy and archive lineage.
  • Strings and indicators. Indexed strings, FLOSS-decoded and stack strings, URLs, hosts and paths as exact values.
  • Rules and capabilities. YARA matches by rule name; capa capabilities grouped so they read as evidence, not as the verdict.
  • Ghidra and similarity. Verified Ghidra exports for chat later; TLSH and ssdeep for near matches across the library.

AI that must cite

A local model, reached through an OpenAI-compatible gateway, investigates inside a typed broker. Every tool call is validated, every exchange is recorded, and every finding names the evidence rows it rests on.

  • Evidence-bounded. The model sees only the saved evidence slices the broker hands it. It cannot fetch, browse or run anything.
  • Typed tools. Each call is checked against a schema before it runs; a malformed call is recorded and refused.
  • Budgets. Actions, runs and wall time are capped per analysis. Exhaustion is a journal entry, not a crash.
  • Pause, take over, stop. An analyst can hold AI actions at any point and continue by hand.
  • No self-granted power. Model output cannot add capabilities or run host commands.
  • Ghidra chat and MCP. Ask questions over verified Ghidra exports in the portal, or from your own tools through an authenticated read-only MCP endpoint.

What the guest tried to reach

Every dynamic run's saved network events become exact indicators: hosts and ports with their outcome, DNS names and resolvers, HTTP URLs, TLS server names. Each value searches the library for every other sample that carries it.

  • Exact by default. Indicators are shown and copied as exact values. Defanging is an explicit, remembered choice for pasting into mail or tickets.
  • Cross-sample links. A shared network destination links samples deterministically, with no model in the loop.
  • Honest gaps. When the guest network never answers, the report records a coverage gap, not a clean network section.

The lab, and its journal

Lab is the screen that opens. It says which workers are admitting work, what each paused worker is holding, how many slots are leased and which family claims wait on a person. A paused analysis is counted as waiting everywhere, so the queue cannot call itself clear while work is owed.

  • Every switch asks why. Pausing or resuming a worker requires a reason, and the reason goes into the journal with the change.
  • One journal for the lab. Who asked, why, what was expected and what the controller observed, newest first, filterable by action type, linked to the sample and analysis.
  • Projects, roles, tokens. Admin, Viewer and Developer roles, one-time setup links, project-scoped service tokens and withdrawable egress grants.
  • Health and alerts. Worker reachability and model availability on every screen; alerts to ntfy or a webhook.

Ten sections, every time

The report stage writes the same ten sections for every sample, in the same order, with a coverage note wherever a section has nothing it can establish. Absence is never inferred.

  • Immutable revisions. A new cycle writes a new report revision; the previous one stays, and the two can be compared section by section.
  • Artifacts kept as they are. Screenshots render as images, telemetry as tables, binaries as hex. Raw bytes and the verified download are one control away.
  • Exports. JSON exports carry evidence metadata and the readable report; original artifact bytes download separately.

Private, by design

Athena runs inside Team AER's lab and its repository is private. The portal at sandbox.brainfc.uk signs in existing accounts only; there is no public upload. If you do defensive malware analysis and want to compare notes, or run it in your own lab, write to us.

Use is limited to samples you are authorized to handle. Athena takes its workflow cues from ANY.RUN and does not claim parity with it. The live AI research cycle is still being proven under load.
