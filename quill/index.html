How it works

One worker, seven stages, every one of them checkpointed. A restart picks up where it stopped, and progress streams to the page over server-sent events.

  1. Drop a file. Resumable tus uploads in 64 MB chunks, up to 10 GB, from anywhere in the app. A dropped connection resumes at the last chunk, not from zero.
  2. Probe and extract. ffprobe reads the container; ffmpeg pulls a clean audio track.
  3. Tell the speakers apart. nvidia/Nemotron-3-Diarization runs on CPU in its own PyTorch venv and labels up to 8 speakers.
  4. Transcribe each turn. Speech-to-text goes through your OpenAI-compatible gateway’s STT jobs API, one speaker turn at a time.
  5. Read the screen, write the notes. Scene changes and transcript cues pick key frames; a vision model reads them; a text model writes the TL;DR, chapters, decisions and action items, each grounded to a timestamp.

If a model is switched off in the gateway, the stage that needs it pauses and resumes on its own when the model is back. A pause is never counted as a failure, and nothing already done is lost.

Take it with you

Every meeting exports from the same menu, on the meeting page and on each card in the library.

  • Notes (Markdown).mdThe notes as a document: paste them into a wiki, an issue or an email.
  • Transcript (TXT).txtThe speaker-attributed transcript as plain text.
  • Subtitles (SRT).srtTimed captions for a video player or an editor.
  • Subtitles (VTT).vttThe same captions for the web.
  • Everything (JSON).jsonThe whole meeting as data, for your own tools.
  • Diarization (RTTM).rttmWho spoke when, in the format diarization tools share.

Built for a small team

  • Admins and members. Admins invite people, reset passwords and pick the models; everyone else uploads, reads and shares.
  • Invites without a mail server. Invites and password resets are one-time links Quill shows once. Copy the link or a ready-to-send message and pass it on however you like.
  • Share one meeting, not the library. Can view or can edit, per person or for everyone on this Quill. A shared meeting carries its owner’s name on the cover.
  • Sign out a device. Account settings list where you are signed in and end any session.

Run it yourself

The app side needs no GPU: Python 3.12 with FastAPI, SQLite with WAL and FTS5, one worker process, ffmpeg, and the diarizer in its own PyTorch-CPU venv. The React frontend is a static build served by nginx in front of the API.

What your gateway must provide

Quill talks to one OpenAI-compatible gateway and nothing else. The models run wherever that gateway puts them. It expects:

  • POST /v1/chat/completions with JSON-schema structured output and a model that accepts images, for frames and notes.
  • A durable speech-to-text jobs API: POST /v1/audio/transcriptions/jobs, then GET the job, its result, or DELETE it.
  • GET /catalog.json with each model’s status, so Quill can pause when a model is disabled rather than fail.

Team AER runs it behind its own gateway, with Avifors sharing one GPU between the speech, vision and text models. Any gateway with the same routes works. Model weights keep their own licences.

Production install
git clone https://github.com/Team-AER/quill.git
cd quill
# one unprivileged Proxmox container, CPU only
deploy/provision-lxc.sh root@pve <CTID>
# tests, build, release; rolls back on failure
deploy/deploy-lxc.sh root@pve <CTID>
# then set QUILL_GATEWAY_URL and QUILL_PUBLIC_URL
# in /etc/quill/quill.env, restart quill-api and
# quill-worker, and put a TLS reverse proxy in front

The scripts target a Proxmox LXC and install everything inside the container: systemd units for the API and the worker, nginx for the static build, nightly SQLite backups, and releases that roll back on their own if a check fails. deploy/README.md has the layout, the reverse-proxy settings uploads need, and recovery for a locked-out admin.

Try the reader without a gateway (mock API)
git clone https://github.com/Team-AER/quill.git
cd quill/frontend && npm install && npm run dev

The frontend dev server includes a mock of the whole API with sample meetings, people and shares, so you can try the reader before wiring up a gateway.
